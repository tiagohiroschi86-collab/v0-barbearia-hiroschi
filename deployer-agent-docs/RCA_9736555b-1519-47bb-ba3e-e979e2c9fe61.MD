## Blocker 2 — Frontend install fails: ERR_PNPM_IGNORED_BUILDS (Code fix)
Both prior runs failed at `build_image` → frontend `pnpm i --frozen-lockfile`:
- Run `9736555b-1519-47bb-ba3e-e979e2c9fe61` (2026-10-18 22:28)
- Run `6a7bc7dc-7b0a-4aaa-94f7-78f0a0c62e31` (2026-10-18 22:12)

Build log (AWS CodeBuild, step #12 [builder 5/8]):
```
[WARN] The "pnpm" field in package.json is no longer read by pnpm.
       The following keys were ignored: "pnpm.onlyBuiltDependencies".
✓ Lockfile passes supply-chain policies
Error: ERR_PNPM_IGNORED_BUILDS
  × installing dependencies
  ╰─▶ Ignored build scripts: @firebase/util@1.15.1, protobufjs@7.6.2, sharp@0.34.5
  help: Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.
[RETRY] All 3 attempts failed → exit code 1
```

### Root cause
The pnpm version in the Next.js base image no longer reads the `pnpm` field from `package.json`. The project declares its approved native-build dependencies under the **deprecated** `package.json` key `pnpm.onlyBuiltDependencies`, so pnpm ignores it. With no approvals in the location pnpm now reads, the packages that ship native build scripts (`sharp`, `protobufjs`, `@firebase/util`) stay un-built, and the strict build policy turns that into the fatal `ERR_PNPM_IGNORED_BUILDS`.

This is a **source/config** problem, not a manifest problem — no manifest overrides exist for this deployment (it uses the stock `nextjs_mongo_shadcn_base_image` templates), and the build command itself is correct. (Note: I could not reproduce in an eph sandbox — spawn failed 3× platform-side — but the build log is conclusive.)

### Fix (E1 / main agent, in the user's repo)
Move the approved-builds list to the location modern pnpm reads. Create/repo-root `pnpm-workspace.yaml`:
```yaml
onlyBuiltDependencies:
  - sharp
  - protobufjs
  - '@firebase/util'
```
(and remove the now-ignored `pnpm.onlyBuiltDependencies` block from `package.json`). Commit the updated `pnpm-lock.yaml` if it changes.
