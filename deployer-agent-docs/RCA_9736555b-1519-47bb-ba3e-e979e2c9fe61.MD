# RCA — hiroschi-dev-preview (deployment 1d7860df-0ca5-4a6d-9d9a-5d79a122a39e)

## Summary
The deploy cannot proceed for **two independent reasons**. Both are outside the deployer agent's control, so no `resume_pipeline` was fired (it would fail immediately on credits, and the build would then fail again on the pnpm issue — wasting ECU).

## Blocker 1 — Insufficient credits (immediate, non-retryable)
The `trigger_indie` step returned:
```
insufficient_credits — Required: 50, Available: 44.14794118519998 (retryable:false)
```
The account balance (44.15 ECU) is below the 50 ECU this deploy requires. The pipeline is gated here and cannot start until the balance is topped up. **The deployer agent cannot add credits.**

## Blocker 2 — Build failure: ERR_PNPM_IGNORED_BUILDS (would still fail even after credits)
The last two runs (9736555b, 6a7bc7dc) both failed at **build_image** during `pnpm i --frozen-lockfile`. Build log (run 9736555b, step #12 `builder 5/8`):
```
[WARN] The "pnpm" field in package.json is no longer read by pnpm.
       The following keys were ignored: "pnpm.onlyBuiltDependencies".
Error: ERR_PNPM_IGNORED_BUILDS
  × installing dependencies
  ╰─▶ Ignored build scripts: @firebase/util@1.15.1, protobufjs@7.6.2, sharp@0.34.5
  help: Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.
```
Retried 3× by the build harness; all 3 attempts failed → terminal build failure.

### Root cause
The frontend `package.json` declares the dependency build-script allow-list under the **`pnpm.onlyBuiltDependencies`** field. pnpm 10+ (the version in the build base image) **no longer reads that field from `package.json`** — it moved to `pnpm-workspace.yaml`. Because the allow-list is therefore empty from pnpm's view, the packages that ship native build scripts (`sharp`, `protobufjs`, `@firebase/util`) are ignored, and pnpm hard-errors with `ERR_PNPM_IGNORED_BUILDS` instead of warning.

This is a **source-config problem in the user's repo**, not a manifest/plumbing problem:
- No manifest override exists in GCS for this deployment (confirmed via `get_deployment_manifest` → `not_found`); the build uses the stock `nextjs_mongo_shadcn_base_image` template.
- The fix belongs in the app's package manager config, not the Dockerfile/build script.

### Fix (E1 / code)
Move the allow-list out of `package.json`'s `pnpm` field into **`pnpm-workspace.yaml`** at the repo root (same dir as the lockfile):
```yaml
onlyBuiltDependencies:
  - sharp
  - protobufjs
  - '@firebase/util'
```
(Remove the now-ignored `pnpm.onlyBuiltDependencies` block from `package.json`.) Then commit the updated `pnpm-workspace.yaml` (and regenerate the lockfile if needed) so `pnpm i --frozen-lockfile` approves those build scripts and no longer errors.

## Verification note
The eph sandbox could not be used to inspect `package.json` directly — `spawn_eph_pod` failed 3× with "pod reached terminal phase 'Failed' before becoming Running" (sandbox infra). The root cause above is therefore established from the **build log warning + error text**, which are explicit and unambiguous, rather than sandbox-reproduced.

## Order of operations for the user
1. Top up credits so balance ≥ 50 ECU (needs ~+6 ECU).
2. Have E1 apply the pnpm config fix above (otherwise the build will fail again and burn the credits).
3. Redeploy.
