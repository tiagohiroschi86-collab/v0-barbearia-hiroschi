## Root cause — two independent, confirmed factors

### Factor A — the deployed source still has the old package.json
The log prints, on every attempt:
`[WARN] The "pnpm" field in package.json is no longer read by pnpm. The following keys were ignored: "pnpm.onlyBuiltDependencies".`
This WARN can only appear if the package.json in the pulled/built source **still contains a `pnpm` field** with `pnpm.onlyBuiltDependencies`. So the described fix (pnpm field removed) was NOT present in the source this run built. Either the edit was never saved into the preview pod's `/app` (what the pull_source step copies), or a stale state was deployed.

### Factor B — the Dockerfile never copies pnpm-workspace.yaml before install (this is the decisive one)
The dependency layer right before install is:
`#11 [builder 4/8] COPY package.json yarn.lock* package-lock.json* pnpm-lock.yaml* ./`
Only package.json + lockfiles are copied. **pnpm-workspace.yaml is NOT copied**, and `.npmrc` is not copied either. Then `pnpm i` runs at `#12`.

pnpm 12.14.0 reads `onlyBuiltDependencies` / `allowBuilds` from **pnpm-workspace.yaml** (not from the package.json `pnpm` field — see Factor A's WARN). Because that file is absent at install time in the build, the approved-builds list is empty, so pnpm ignores the build scripts for @firebase/util, protobufjs and sharp and hard-fails with ERR_PNPM_IGNORED_BUILDS.

This fully explains why `pnpm@12.14.0 i --frozen-lockfile` **succeeds locally** (pnpm-workspace.yaml is present in the working dir) but **fails in the build** (the file was never copied into the deps layer). Removing the package.json pnpm field alone (Factor A) will NOT fix the build — the workspace-level allowBuilds has no effect because the file isn't there at install.

## Recommended fixes
1. (Code / E1) Confirm the package.json `pnpm` field is actually removed and saved in the preview `/app`, since the built source still had it. Necessary for cleanliness but NOT sufficient on its own.
2. (Deployer manifest / Dockerfile) Update the dependency-copy layer so pnpm-workspace.yaml (and .npmrc if used) is copied before `pnpm i`, e.g.:
   `COPY package.json yarn.lock* package-lock.json* pnpm-lock.yaml* pnpm-workspace.yaml* .npmrc* ./`
   This makes the user's allowBuilds/onlyBuiltDependencies list visible at install, which is what allows the sharp/protobufjs/@firebase/util build scripts to run. This is a manifest change applied on the next deploy. Per the request, no redeploy was performed.

## Not the cause
Not a tier/OOM issue, not a secret issue, not a missing dependency in package.json — the install resolves all 269 packages fine and only fails on the approved-builds gate.
